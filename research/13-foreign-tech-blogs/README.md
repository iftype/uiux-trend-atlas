## 읽는 방법

1. 완성 화면보다 문제와 제약을 먼저 기록한다.
2. 정성적 주장과 실제 측정 지표를 구분한다.
3. 한 회사의 해법을 보편 규칙으로 옮기지 않는다.
4. 디자인 시스템 문서와 실제 제품 구현 글을 함께 읽는다.
5. 접근성·성능·프라이버시가 빠진 사례는 별도 위험으로 표시한다.
